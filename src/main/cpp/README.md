# Native launcher

`launcher.cpp` is the entire native component: a tiny executable that `dlopen()`s the Node runtime
named by the `ST_NODE_LIB` environment variable and calls `node::Start()` through `dlsym`. It is
built into `libstnode.so`, shipped in `jniLibs`, and extracted to `nativeLibraryDir` with the
executable bit set; the app runs it as a child process.

**Why a launcher?** On modern Android (`targetSdk >= 29`), an app cannot `exec()` files from its
writable data directory (the W^X restriction). Executing from the read-only `nativeLibraryDir` is
allowed. Running the runtime in its own process (rather than in-process via JNI) means
`process.execPath`, `child_process`, and npm behave normally.

**Why `dlopen` instead of linking?** The launcher does not link `libnode.so` at build time. It
loads whatever path `ST_NODE_LIB` points at, which lets the runtime be either
- bundled — a path in `nativeLibraryDir`, or
- downloaded on first run — a path in app storage.

Validated on-device (Android 16 / arm64): a runtime copied into app storage and loaded this way
boots Node and serves SillyTavern.

Notes
- We build the launcher with `-Wl,-z,max-page-size=16384` for 16 KB page devices.
- `node-include/` is generated by `ci/fetch_node_runtime.sh` and is no longer required by the
  launcher (kept for reference).
