# Native launcher

`launcher.cpp` is the entire native component: a tiny executable that links the prebuilt
`libnode.so` and calls `node::Start()`. `CMakeLists.txt` builds it into `libstnode.so`, which is
shipped in `jniLibs`, so Android extracts it to `nativeLibraryDir` with the executable bit set.
The app then runs it as a child process.

**Why a launcher?** On modern Android (`targetSdk >= 29`), an app cannot `exec()` files from its
writable data directory (the W^X restriction). Executing from the read-only `nativeLibraryDir` is
allowed. This gives the app a *real* Node process — so `process.execPath`, `child_process`, and
npm behave normally — without compiling Node from source.

Notes
- `node-include/` is generated by `ci/fetch_node_runtime.sh` (the pinned Node headers).
- All binaries we build are linked with `-Wl,-z,max-page-size=16384` for 16 KB page devices.
- The launcher is deliberately minimal; all application logic lives in `src/main/java/app/stmobile/`.
